# Nix environment

## Machines

- `cinderace`: NixOS desktop, x86_64-linux.
- `ninetales`: MacBook, nix-darwin, aarch64-darwin.
- Both are defined in the `~/nix` flake. Home Manager is standalone, separate
  from the system configuration.

## Tools

- Never install globally: no `pip install --user`, `npm -g`, `cargo install`,
  `go install`, `brew install`, `nix profile install` or `nix-env -i`.
- One-off command: `, <cmd> [args]` (comma) runs it from nixpkgs without
  installing.
- Several tools or a specific package: `nix shell nixpkgs#<pkg> -c <cmd>`.
- Run a flake app: `nix run nixpkgs#<pkg> -- [args]`.
- Find which package provides a binary: `nix-locate bin/<cmd>`.
- Tools I want permanently go in `~/nix` as a Home Manager package; propose the
  change instead of working around it.

## Projects

- Each project has a `flake.nix` dev shell loaded by direnv (`.envrc` with
  `use flake`). Add toolchains, libraries and CLIs to the dev shell, not to the
  system.
- After changing the dev shell: `direnv reload`, or run commands with
  `nix develop -c <cmd>` when direnv is not active in the agent's shell.
- New project: `nix flake init -t ~/nix#<template>`, with templates `clojure`,
  `gleam`, `ocaml`, `python`, `rust`, `zig`.
- Flakes only see files tracked by git: `git add` new files before
  `nix build`, `nix flake check` or `nix develop`.

## Dotfiles

- Hand-edited app configs live in `~/nix/home/config/<app>` and are linked into
  `~/.config` as live symlinks. Edit the file in `~/nix`; changes apply without
  a rebuild (restart or reload the app).
- Files in `~` that resolve into `/nix/store` are generated by Home Manager and
  read-only. Change the Nix module that produces them instead.
- Agent instructions and skills live in `~/nix/home/config/ai`.

## Applying changes

- Home: `nh home switch` (agents can run it). Build only: `nh home build`.
- System: `nh os switch` on NixOS, `nh darwin switch` on macOS. Both need
  `sudo`.
- `sudo` needs a YubiKey touch on a real terminal, so agents cannot run it.
  Build with `nh os build` or `nh darwin build` to check, then hand me the
  switch command.
- Adding a new linked config needs a home switch; editing an existing one does
  not.

## Services and processes

- NixOS: system services are systemd units declared in `~/nix`; never enable
  or edit units by hand under `/etc`. User services run under
  `systemctl --user`.
- macOS: services are launchd agents declared in `~/nix`.
- Nix-wrapped programs run as `.<name>-wrapped`, so `pkill -x <name>` misses
  them. Use `systemctl --user stop <unit>` or
  `systemctl --user kill --kill-whom=main <unit>` for services, and
  `pkill -f <name>` otherwise. `pkill` without `-f` only matches the first 15
  characters of the process name.
- `/etc`, `/usr` and most of `/` are read-only or regenerated on switch. Paths
  like `/usr/bin/<tool>` do not exist on NixOS; use `/usr/bin/env` or
  `/run/current-system/sw/bin`.
- Prebuilt dynamically linked binaries (downloaded releases, pip wheels with
  native code) do not run on NixOS without patching. Prefer the nixpkgs
  package or a dev shell that provides the library.

## Writing Nix

- Format with the repository formatter (`nix fmt`).
- Pin with a reason: state why an override or `mkForce` exists and when to
  drop it in the commit message, not in a comment.
- Look up options before using them: `man home-configuration.nix`,
  `man configuration.nix`, or search the nixpkgs, NixOS and Home Manager
  sources. Do not guess option names.
- Check changes with `nix flake check` or by building the affected
  configuration before reporting done.
