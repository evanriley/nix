# Nix packaging

## Before writing a derivation

1. Check nixpkgs first: `nix search nixpkgs <name>`, and the package source
   under `pkgs/by-name/<first-two-letters>/<name>/package.nix` in the nixpkgs
   repository. Prefer the nixpkgs package, then an override, then a new
   derivation.
2. Check whether upstream ships a `flake.nix` with a package output; use it as
   a flake input if it is maintained.
3. Read the upstream build instructions: build system, native dependencies,
   runtime dependencies, tests.

## Placement

- Tools for my machines: `~/nix/modules/packages/<name>.nix` defining
  `perSystem.packages.<name>`, consumed in modules as
  `inputs.self.packages.${pkgs.stdenv.hostPlatform.system}.<name>`.
- Scripts in `~/nix`: the `mkScript` helper with the source in a `_scripts`
  directory, `runtimeInputs` for every command the script calls.
- Project artifacts: `packages.default` in the project's `flake.nix`, built
  with the builder the project template already uses.

## Fetchers and hashes

- Pin sources to a tag or commit with `fetchFromGitHub` (`owner`, `repo`,
  `rev` or `tag`, `hash`). Avoid `builtins.fetchGit` and unpinned URLs.
- Get a hash by building with `hash = lib.fakeHash;` and copying the `got:`
  value, or `nix-prefetch-github <owner> <repo> --rev <rev>` /
  `nix store prefetch-file <url>`.
- Vendored dependency hashes (`cargoHash`, `vendorHash`, `npmDepsHash`) use the
  same fake-hash loop, and must be refreshed on every version bump.
- Never copy a hash from another package or a web page.

## Builders

- Rust: `rustPlatform.buildRustPackage` with `cargoHash`, or crane in project
  flakes (the rust template uses crane).
- Python: `python3Packages.buildPythonApplication` with `pyproject = true`, or
  uv2nix in uv projects (the python template uses it).
- Go: `buildGoModule` with `vendorHash`.
- Node: `buildNpmPackage` with `npmDepsHash`.
- OCaml: `ocamlPackages.buildDunePackage`.
- Clojure: clj-nix with a `deps-lock.json` generated by `deps-lock`.
- Zig: `stdenv.mkDerivation` with `zig.hook`.
- Gleam: nix-gleam `buildGleamApplication`.
- Prebuilt binaries: `autoPatchelfHook` on Linux; last resort.

## Derivation rules

- `pname`, `version`, `src`; `meta.description`, `meta.license`,
  `meta.mainProgram`, `meta.platforms`.
- `nativeBuildInputs` for build-time tools, `buildInputs` for linked
  libraries.
- Runtime commands reach the program through `makeWrapper`
  (`wrapProgram --prefix PATH : ${lib.makeBinPath [ ... ]}`), not by assuming
  they are on the user's PATH.
- Keep `doCheck = true` when tests work in the sandbox; when disabling them or
  single tests, say why in the commit message.
- Patches live next to the derivation as `.patch` files; the commit message
  says when to drop them (upstream PR or version).

## Overrides

- Version bump or source change: `overrideAttrs (old: { version = ...; src = ...; })`,
  plus refreshed vendor hashes.
- Changed dependencies or flags: `override { ... }` for function arguments,
  `overrideAttrs` for derivation attributes.
- Every override's commit message says when to drop it.

## Verify

- `nix build .#<name> -L`, then run `./result/bin/<program> --version` or a
  real invocation.
- `nix flake check` in `~/nix`.
- On macOS-relevant packages, confirm `meta.platforms` and that nothing is
  Linux-only.
